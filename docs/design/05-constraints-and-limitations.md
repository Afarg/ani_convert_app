## 1. 目検出の精度限界

> **更新履歴（実機検証で判明）**: 当初はHaar cascadeを主方式とする前提でこの節を書いていたが、`02-generation-pipeline.md` §2.1の更新履歴のとおりHaar cascade自体が使えず、**彩度ベースのヒューリスティックのみ**で実装した。以下はその実装に対する精度限界。

| 入力の種類 | 彩度ヒューリスティックでの検出精度 |
|---|---|
| 目の色が肌・髪より明確に高彩度なイラスト（今回の実機検証キャラクター等） | 実機検証で良好。左右対称フォールバックと合わせて両目とも正しい位置に検出できた |
| 目の色が肌・髪と彩度的に近い、またはモノクロ調のキャラクター | 低下する可能性がある（彩度差という前提そのものが弱まるため） |
| 実写に近い人物写真 | 未検証。肌・目の彩度差が薄いことが多く、イラストより精度が下がる可能性がある |
| 非人間キャラクター（目に相当する部位が無い等） | 検出されない、または誤検出する可能性がある |

検出できない入力は一定数残る想定。**その場合はまばたきフレームを生成せず、静止表示のままにする**（無理に描き足さない、`img_to_pixcel_app`から一貫している方針）。左右対称フォールバック（`02-generation-pipeline.md` §2.1）は、キャラクターが左右対称な正面/斜め向きであることを前提にしているため、真横向きの`side`ビューには適用しない方がよい（実装時に`view`ごとに有効/無効を切り替える想定）。

## 2. 脚部領域ヒューリスティックの限界

「bounding boxの下35%を脚とみなす」という単純な比率ベースの推定は、以下のような入力では意図通りに機能しない可能性がある。

- 脚が無い/極端に短いデザイン（幽霊、球体状のキャラクター等）
- 椅子に座っているなど、脚が隠れているポーズの入力画像
- 2頭身から大きく外れる特殊なプロポーション
- **丈の長いジャケット・コート等、`leg_fraction`の境界より下まで裾が伸びる服装**（2026-07-29追記: 実際に発生し修正済み。脚部領域のうちシフトするのは下側`shift_fraction`分のみに縮小し、裾が脚と一緒に持ち上がって切れ込みができる問題を軽減した。ただし裾が`shift_fraction`後の境界より下まで伸びる、さらに丈の長いデザインでは依然として起こりうる、`02-generation-pipeline.md` §3更新履歴参照）

これらは`img_to_pixcel_app/docs/design/04-constraints-and-limitations.md` §3の入力ガイドライン（1体・中央寄り等）である程度軽減されるが、完全には防げない。**歩行フレームの見た目が不自然になる既知の限界として受け入れる**（強制的にブロックはしない）。

## 3. ライセンス面

`opencv-python-headless`はApache License 2.0。目検出はヒューリスティックのみ（モデルファイル不使用）のため、`img_to_pixcel_app`側の`rembg`モデル重みのような追加のモデルライセンス確認は不要。

ダウンロード済みだが現状未使用の`models/haarcascade_eye.xml`（OpenCV公式リポジトリから取得、ユーザー許可済み）については、将来Haar cascadeを追加する場合に備えて残置している。Intel由来でOpenCV本体と同じBSD/Apache系ライセンスの範囲内で配布されているものだが、実際に使う段階で改めてライセンス条項を確認すること。

## 4. スコープ外の入力

- まばたき・歩行以外のポーズ差分（`00-overview.md` §3で明記）。
- アニメーションGIF等の動画ファイルの直接入力。あくまで`img_to_pixcel_app`が出力した静止画バンドルを入力とする。
