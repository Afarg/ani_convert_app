# 00. 概要 — アニメーション差分生成ツール（仮称: PixelAnimator）

対象読者: 本ツールの実装者。
関連: `../../img_to_pixcel_app`（PixelForge、仮称）— 本ツールの入力を作る前段ツール。`agents_app`（Agent Village）— 本ツールの出力を最終的に表示する側（`agents_app/docs/design/07-directional-animation-support.md`にAgent Village側で必要な対応を記載）。

**実装状況**: 実装済み・実機検証済み（フェーズ1: 正面のみのテストバンドルで、まばたき・歩行差分の生成、FastAPI+ブラウザUIでのプレビューまで確認済み）。フェーズ2・3（斜め・横向き・後ろ向きを含む複数アングルバンドル）は未検証（`img_to_pixcel_app`側の複数アングル入力UI自体が未実装のため）。

---

## 1. これは何か

- `img_to_pixcel_app`（PixelForge）が生成したピクセルキャラクター画像（1〜4アングル）を読み込ませると、**まばたき**と**歩行**の差分フレームを自動生成するスタンドアロンのソフト。
- 生成した差分フレームをAgent Villageに導入すると、キャラクターが目を閉じたり歩いたりするアニメーションとして表示できるようにする。
- PixelForgeと同様、**Agent Village専用ではない汎用ツール**として設計する（他の用途にも使い回せる）。

## 2. 背景・経緯

ユーザーとの検討の結果、以下の方針で合意している（2026-07-27〜28）：

1. **歩行アニメーションは「1枚の画像から4方向を捏造する」のではなく、「利用者が提供した分のアングルだけ生成する」方針**にする。1枚の写真には写っている角度の情報しか無く、無い視点を機械的に作り出すことはできない（生成AIが必要な領域であり、今回のスコープ外）。
2. 歩行の差分自体は、**どのアングルであっても**（正面・斜め・横向き・後ろ向きのどれでも）、「脚部のピクセルを画像内で動かす」という決定論的な処理で作れる。新しい視点を作る処理ではなく、既存の1枚の画像内で脚の位置を変えるだけなので、提供されたアングルの数だけ同じ手法を適用できる。
3. **まばたき**は、元画像（ピクセル化する前の高解像度画像）から目の位置を検出し、その座標をピクセル化の縮小率に合わせて変換すれば、最終ピクセルグリッド上のどのマスが目にあたるかが分かる。そこを閉じ目色で塗り替えるだけで生成できる。

これらはいずれも「新しい情報を捏造しない、既にある情報の範囲内で処理する」という一貫した原則に基づく（`img_to_pixcel_app`でAI生成を見送った判断と同じ考え方）。

## 3. スコープ

### やること

- `img_to_pixcel_app`が出力する「キャラクターアセットバンドル」（`../../img_to_pixcel_app/docs/design/06-multi-angle-input.md` §5）を入力として受け取る。
- バンドルに含まれる**アングルごとに**、以下を生成する:
  - まばたきフレーム（目を閉じた版、1枚）
  - 歩行フレーム（脚の位置を変えた版、1枚。既存の立ちフレームと合わせて2フレームの歩行ループになる）
- 生成したフレーム一式を、Agent Villageが読み込める形式（`04-output-format-and-agent-village-handoff.md`）で書き出す。
- 提供されなかったアングルはスキップする。`img_to_pixcel_app`側は3フェーズ構成（`../../img_to_pixcel_app/docs/design/06-multi-angle-input.md`）: フェーズ1（正面のみ）・フェーズ2（+斜め、推奨）・フェーズ3（+横向き+後ろ向き、フル）。バンドルに`front`しか無い（フェーズ1）場合もあり得るため、**アングルが1つしか無いケースを前提外にしない**。

### やらないこと（明示的にスコープ外）

- 提供されていないアングルの生成（`img_to_pixcel_app`側のスコープ外事項と同じ、二重に強調しておく）。
- まばたき・歩行以外の差分（作業ポーズ・お祝いポーズ等、`agents_app/docs/design/01-visual-concept.md` §3.2にある他のアニメーション種別）。将来の拡張候補として言及するに留める。
- Agent Village本体側の再生ロジックの実装（`agents_app/docs/design/07-directional-animation-support.md`側の担当）。

## 4. 名称

本設計書内では仮称として **PixelAnimator** と呼ぶ。実装時に正式名称を決めてよい。
